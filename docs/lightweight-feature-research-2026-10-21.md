# 轻量科研工作台实用功能调研

调研日期：2026-10-21。对照版本：v261021.3 当前工作区源码。

## 结论与依据

建议优先考虑：**技术论文双位置阅读、精确定位与返回、按项目恢复工作现场**。这三项直接利用已有 PDF、笔记、搜索和 Agent，价值来自减少日常重复操作。另有两个条件性候选：**工科计算便签**和**外部工具轻量连接**。

本次查阅了 Sioyek、Obsidian、Zotero、Soulver、Calcpad 等官方资料，并对照当前源码，区分已有能力与新增范围。官方资料能证明这些设计已有实际产品采用；下面的排序是结合本项目的判断，尚未经过真实使用频次验证。本次没有重新进行完整 UI 测试，也没有修改业务代码。

用户已经否定实验台账、证据矩阵、验收管理、快照、收件箱等上一轮方向，本轮不再将其列为候选。大量实验数据继续由专门工具承接。

## 当前能力核对

| 已有能力 | 这次建议新增的部分 |
| --- | --- |
| PDF 阅读、批注、页码续读、左右区域宽度调整 | 同一 PDF 的两个独立阅读位置；公式、图表的临时预览 |
| 全局搜索文档、待办、聊天等内容 | 命中后跳到具体段落或消息；PDF 内查找与命中定位 |
| 最近工作入口、最近文献、单文献续读 | 按项目恢复一组相关资源和视图状态 |
| 外部 Markdown 编辑器、打开项目目录 | 按具体资源连接外部工具，保留来源标识 |
| RSS 资讯入口 | 本轮不建议另建文献推荐系统 |

核对位置：`web/literature.js` 的阅读状态及 `openByDocument`；`web/app.js` 的 `openSearchResult`；`web/research-ui.js` 的 `remember/recent`。当前全局搜索入口打开相应文档或会话，未在该入口看到命中位置参数；文献阅读代码未检索到 PDF 目录或全文查找控制器。上述是源码观察，不作为全应用功能缺失的测试结论。

## 1. 技术论文双位置阅读：优先

**场景：**正文在第 12 页讨论第 4 页的公式或图。临时查看后，还能继续读第 12 页原来的位置。

Sioyek 提供参考内容预览及第二位置窗口，用于减少正文与图表、公式之间的往返。这是面向技术阅读的具体设计依据。[Sioyek 官方功能介绍](https://sioyek.info/)

最小范围：

- 同一篇 PDF 增加一个可关闭的辅助阅读区，两个位置独立滚动。
- 支持“把当前页固定到辅助区”，先用手动页码和已有 PDF 链接导航。
- 保存主阅读位置；辅助区关闭后主视图保持原位。
- 宽屏使用并排区域，较窄窗口使用临时浮层。

现有左右宽度调整可以继续使用；这里增加的是独立的第二阅读位置。自动识别所有公式引用、跨文献对照可以后续评估。

验收场景：主区第 12 页、辅助区第 4 页；缩放或关闭辅助区后，主区页码、滚动位置及批注选择仍正确。

预计复杂度：中。主要成本在渲染内存、快捷键作用范围和两个视图的状态隔离。

## 2. 精确定位与返回：优先

**场景：**搜索记得的一句话，直接看到那段话；点开 Agent 的资料引用后，能返回原来的对话位置。

Zotero 的批注笔记保留回到 PDF 页面的链接，说明“从整理后的内容回到原始上下文”值得作为独立交互设计。[Zotero PDF 阅读器与笔记文档](https://www.zotero.org/support/pdf_reader)

最小范围分两步：

1. 文档和聊天搜索结果携带命中位置，打开时滚动到对应段落或消息并短暂标亮；增加前进、后退位置历史。
2. PDF 增加当前文献内文字查找、上一处/下一处、目录导航；再评估将 PDF 正文纳入全局搜索。

随后让笔记链接和 Agent 引用复用同一种定位能力，覆盖“文档＋段落”“会话＋消息”“PDF＋页码/批注”。

验收场景：一句话在长文档、长会话中分别出现多次，用户能选中具体命中；返回后恢复原来的滚动位置。源文档被修改时，允许退回打开文档并提示位置变化。

预计复杂度：中至高，适合分步交付。文字型 PDF 可先支持；扫描件 OCR 和全库 PDF 索引另行评估。

## 3. 按项目恢复工作现场：优先

**场景：**从项目 A 切到项目 B，第二天回到 A 时，能接着看原来的文献、笔记和 Agent 会话。

Obsidian 的 Workspaces 保存打开的文件、标签及侧栏布局，可按任务切换。[Obsidian Workspaces 官方文档](https://obsidian.md/help/plugins/workspaces)

最小范围：每个项目记住当前文献及页码、笔记及滚动位置、Agent 会话，以及甘特图筛选和时间范围。项目入口提供“继续工作”。仅保存位置和界面状态，沿用现有资料。

第一版可以恢复当前页面，并给出相关资源的一键入口；无需同时展示所有模块。确认有需要后，再考虑多个命名工作场景。

验收场景：A、B 两个项目的阅读页码、对话及甘特图筛选互不覆盖；资源被删除或改名时，其余入口仍能恢复。

预计复杂度：中。跨模块恢复和未保存笔记的处理需要统一规则。

## 4. 工科计算便签：值得小范围验证

**场景：**读论文时随手核算数量级、单位或参数变化，把算式和结果一起插入笔记。

例如：

```text
force = 2 kN
area = 400 mm^2
stress = force / area  → 5 MPa
```

Soulver 将变量、单位和计算放进文本便签；Calcpad 支持工程计算中的物理单位处理。这些产品提供了交互和计算能力的参考。[Soulver 官方介绍](https://soulver.app/)、[Calcpad 官方介绍](https://calcpad.eu/)

最小范围：四则运算、变量、常用单位换算、量纲不兼容提示，以及“插入算式与结果到当前笔记”。采用确定性的计算引擎；保留输入表达式和结果，便于检查。

先不加入大表格、数据拟合、绘图、仿真或复杂编程。实际价值取决于使用者是否经常进行小规模手算，因此排在阅读与导航之后。

验收场景：上述应力计算得到 5 MPa；长度与时间相加显示明确错误；改动输入后依赖结果正确更新。

预计复杂度：中。单位语义、精度及温度等特殊换算应使用成熟实现并验证。

## 5. 外部工具轻量连接：按使用习惯选择

**场景：**文献在 Zotero 管，代码在编辑器中写，工作台笔记里能直接打开对应条目或文件。

Zotero 提供访问本地资料的官方 Local API，使可选的本机只读连接有实现依据。[Zotero Local API 官方文档](https://www.zotero.org/support/dev/web_api/v3/local_api)

最小范围：资源卡片保存外部标识和打开链接；需要时读取所选条目的基础元数据。先验证一个实际使用的外部工具，再决定是否推广。

如果用户没有使用 Zotero，就没有理由优先开发 Zotero 连接。与其默认导入完整资料库，更适合从“把当前需要的条目关联到项目”开始。

预计复杂度：随工具而变，连接完成后的维护成本也应纳入取舍。

## 低成本配套改进

已有 Ctrl+K 内容搜索可增加操作模式，例如输入 `>` 后查找“新建笔记”“继续项目”“打开原文件”“固定参考页”。Sioyek 的可搜索命令面板可作为参考。它适合作为上述功能的统一入口，独立开发的价值低于前面三项。[Sioyek 官方功能介绍](https://sioyek.info/)

## 推荐顺序与后续验证

建议先做“搜索命中定位＋返回历史”，为引用跳转提供共同基础；随后加入同文献第二阅读位置，再做按项目恢复工作现场。若只选择一个可直观看到新增价值的功能，优先试做双位置阅读。

计算便签先用几个真实手算例子验证使用频率。外部工具连接等确定常用工具后再选型。暂不把专题推送、文献推荐、完整计算环境或更多管理模块加入近期范围。

实现前可在日常使用中观察三个信号：反复查找同一内容的次数、正文与公式图表往返的次数、切换项目后重新打开资料的次数。用这些行为验证优先级，比单纯比较功能数量更可靠。
