# Agent 升级设计与交付范围

## 目标和结构

主 Agent 页面与悬浮助手共用同一个后台运行时、会话和事件流。增强科研任务的执行可靠性、技能复用和来源核查，不增加第二套聊天入口。模型仍由用户已有的供应商配置提供；运行框架可以改善执行与取证，不能承诺不同模型都达到 Codex 的任务表现。

```text
主界面 / 悬浮助手
        ↓ 共享会话、流式事件、停止和草稿确认
持久化运行时 → 计划 / 工具 / 检查点 / 预算 / 重复调用保护
        ├─ 技能：发现元数据 → 激活工作流程 → 按需资源 → 隔离脚本
        ├─ 资料：关键词 / 语义 / 混合检索 → 正文与原始 PDF 核查
        ├─ 记忆：作用域与来源 → 有界 ContextPack
        └─ 交付：中间回答 + 最终正文 + 标题引用 + 技能记录
```

## 本次实现

### 技能包

遵循 SKILL.md 的基本目录契约，采用 YAML 安全解析，支持多行描述、工具列表、metadata.version 和可选 agents/openai.yaml。后者支持展示名称、简短描述、默认提示、allow_implicit_invocation 及工具依赖声明。依赖仅用于诊断，不自动安装、连接或授权。

按以下顺序发现技能，后者覆盖同名技能：

1. 应用内置 app/skills。
2. Workspace/.agents/skills。
3. Workspace/.codex/skills。
4. Workspace/System/Agent/Skills。

不会自动读取主机其他项目或个人 Codex 技能目录。导入现有技能包后，仍需要核对该技能依赖的工具与环境是否受工作台支持。

技能页管理总开关、逐项启停、搜索、ZIP/文件夹/文本导入、资源浏览与环境诊断。完整包先在临时目录校验，再原子安装；拒绝越界、符号链接、重复路径、Windows 特殊文件名及超限包。限制为 128 文件、单个 2 MB、总计 20 MB，ZIP 压缩文件最多 12 MB。

### 按需加载与执行

发现阶段只提供名称、描述等元数据。任务匹配时模型调用 skill_read 激活，用户也可用 $技能名称 明确调用。仅明确调用的技能不会出现在自动选用目录；停用后不可通过工具绕过。

运行时记录激活原因、版本、整个包的内容指纹、读取资源与脚本次数。最多同时加载八个技能；每个激活技能注入至多 12,000 字符的流程，其余按需分页读取。工作流程使用独立参考消息，用户本轮要求优先；上下文压缩保留当前技能块，原始工具证据仍可分页重读。技能包执行期间变化时拒绝使用新脚本，要求重新发起任务，避免不同版本混用。

scripts/ 中的 Python 由已有 Docker 沙箱执行，支持参数数组、显式输入与产物。关闭代码执行、未安装 Docker、镜像或第三方依赖缺失时返回可修正的错误；不会退回宿主机执行。allowed-tools 是工作流程声明，不扩大人设权限；外部 MCP 仍须通过已有设置显式配置。

内置技能扩展为：文献比较、知识整理、研究分析、证据核查、技能编写。长参考和模板独立保存。技能编写可通过 skill_install 生成可审阅草稿，遵循原有确认模式；安装时不会运行脚本。

### 长任务与交付

保留原有计划、暂停、停止、草稿、检查点、断线恢复和分轮正文。最近八次记录中相同工具/参数已执行三次后，运行时阻止重复执行；连续两次触发保护后暂停并保留正文，避免消耗模型额度。继续时可以改用查询、分页或其他方案。

证据规则要求：命中摘要与实际读过的正文分开；作者结论、跨来源推断和工程建议分开；失败/超时不直接当作不可行。已知条目和修订号在公开流、最终回答及历史加载时转换为真实标题；工具原始参数、证据和修订功能保留内部编号。明确索要内部编号时允许展示。

## RAG 索引生命周期

所有模式复用现有构建器：按内容与位置识别分块，同一模型和分块配置下未变化向量直接复用；新增或变化分块才请求嵌入。删除来源从新一代索引移除。完整新一代成功后原子切换，失败或取消保留上一代。

| 方式 | 行为 |
| --- | --- |
| 手动 | 保存并更新索引，立即后台执行；支持取消 |
| 实时 | 服务每 5 秒检查资料文件的时间与大小；连续修改合并，默认等待 15 秒（可设 5–300 秒）后更新 |
| 定期 | 默认每 60 分钟（可设 5–10080 分钟）；本机保存下一次时间，重启后检查到期任务 |
| 清除 | 事务删除全部分块与索引元数据，清空查询缓存并压缩数据库；保留空 SQLite 结构、原始资料和独立长期记忆库，同时关闭自动更新 |

实时与定期可以同时开启。默认均关闭；仅当服务运行、RAG 开启、选择语义/混合模式且已配置接口时执行。文档检查只读文件状态，不嵌入全文；检查覆盖工作台 Markdown 目录，以及启用 PDF 时的文献库 PDF 和登记文件。构建前同步资料索引，以纳入外部新增与删除。

正在构建或取消时不能清除，避免与生成提交竞态。清除不会删除文献或笔记，也不会自动重建。配置指纹变化会使旧向量失效。构建失败在状态中显示，同一批变化不会不断实时重试；可以手动重试、修改资料或等待下次定期更新。手动已建成且资料未变化时，实时检查不重复构建。

本机制运行于工作台本地服务，不是操作系统常驻计划任务。关闭应用期间不调用接口，重启时恢复已保存的定期时间。向量检索仍为有界精确扫描，尚未引入专用 ANN 服务；技能不等同于任意 Codex 插件、Shell 或桌面自动化的完整兼容。

召回数量以用户 `rag_top_k` 设置为统一默认，覆盖聊天工具、原生函数规格、文本工具协议、检索试用 HTTP 接口及长期记忆召回。返回实际 count、有效 limit；工具还记录配置上限与模型指定值，便于区分数量不足和主动缩小检索。候选数足够时设置 12 可实际返回 12 个独立条目，仍受类型、有效来源、匹配程度与记忆字符预算限制。

## 验证方法

优先采用一次性工作区、脚本化模型、本地模拟 Embedding HTTP 服务和浏览器 fixture；不使用用户真实模型额度，不修改真实语料。

后端覆盖明确/隐式/无关/关闭技能、完整包导入与回滚、YAML、路径边界、版本变化、脚本参数、重复调用暂停、标题分片流与原始证据、向量清除、实时合并、定期持久化、开关、复用以及失败回退。

浏览器覆盖技能包资源管理、两个聊天视图、引用跳转、编辑重发与停止、RAG 更新策略及清除、暗色表格悬停对比度和窄屏布局。自动化测试可以证明执行契约；真实科研回答质量仍取决于资料、检索和所选模型，不能从模拟模型测试推断。
