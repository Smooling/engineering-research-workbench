# Agent「本轮参考」实现说明

日期：2026-10-22，2026-10-23 更新。依据 [开发设计](AGENT_CONTEXT_SOURCES_DESIGN.md) 实现第一阶段，包含在 `v261023.1` Windows 构建中。

## 使用

回答底部的“本轮参考”打开对应回答的来源。主 Agent、悬浮助手和任务结果共用同一个面板。普通点击回答中的知识引用，会选中对应来源；Ctrl/Cmd 点击继续使用原有直接导航。

面板提供类型筛选、同一来源的片段/版本选择、复制和打开原条目。宽屏在保留至少 520px 对话宽度时并排显示，可拖动或用方向键调节宽度；空间不足及悬浮助手使用抽屉。Esc 返回原入口，各回答记住最近的选择。正文只作为文本展示，资料中的 HTML 不执行。

参考面板打开时，AI 小球完整显示在面板上层；点击小球会先收起参考面板再打开 AI 对话，避免对话窗继续被覆盖。关闭参考面板后，小球恢复通常的贴边隐藏行为。

“已提供”按本轮至少一次已发起请求的来源实体并集去重；“已引用”只解析回答正文的明确 WikiLink 或条目链接，不根据 `[1]`、同名猜测、代码示例或工具调用次数推断。它们均不表示模型采用了资料或结论已被核实。原始 ID 引用在转为界面标题前解析。

同一来源可有多个进入方式和片段。详情的“各次请求的提供范围”显示内容块完整保留、压缩节选、历史摘录或本次未提供，并标记生成这条回答的请求。完整保留描述的是当时的内容块，不能解读为读取了全文。

原条目跳转复用 `ERWNav` 和历史导航，打开当前版本；历史快照始终保留。当前阶段只保留字符起点、页码和已有读取范围信息，不强行将旧字符位置应用到已改写的正文。原条目删除时仍能阅读和复制历史片段。

## 采集与持久化

新增 `app/agent_sources.py` 统一维护来源范围、结构化 JSON 序列化、请求记录和回答视图。手动引用、页面/选区、历史引用选段、自动记忆、`memory_recall`、`kb_search`、`kb_read`、`workspace_read`、`pdf_read`、`lit_context` 和 `evidence_read` 均在生产内容时附内部范围信息。

2026-10-23 修复 AG-01：普通文件按规范化工作区路径归并，保留全文版本哈希、读取字符范围和实际发送文字；PDF 按文献标识归并、逐页保存提取文字，版本哈希来自提取时同一份 PDF 字节，不使用可能过时的文献注册哈希。文件修改或删除后，来源面板与证据重读仍使用留存快照。空文件或无可提取文字的扫描页不会虚构正文来源；读取结果缺少定位或版本元数据时明确降级为不完整。

压缩处理与范围一起变换：历史摘要保存实际抽取的前缀，工具 JSON 按结构缩短后重新序列化并计算偏移。最终工具协议转换后、HTTP 发起前捕获清单，发送时剥离所有内部来源字段。无额外模型调用；来源采集失败不会重跑工具。

每个实际 HTTP 尝试有独立随机 request ID、逻辑步骤和尝试序号，包括连接重试、流式降级和工具协议回退。准备记录在 I/O 前持久化；写入调用返回后记录请求发起，完整响应/HTTP 错误及网络中断分别记录响应、失败或未知。未知状态不会标成确认送达。

在已有 `System/Agent/brain.sqlite` 中增量创建：

| 表 | 内容 |
| --- | --- |
| `source_runs` | 来源候选、revision、采集错误 |
| `source_requests` | 每次请求的来源块、快照内容/哈希、位置、协议与生命周期 |
| `source_views` | 绑定 session/message 的冻结来源、引用映射与请求范围 |

相同实体、版本、位置和内容使用稳定快照 ID。回答视图保留自身请求列表和状态，继续同一任务不会修改旧回答。快照、清单和单个回答视图均受 12MB 记录上限约束，超出或保存失败显示“记录不完整”。

会话 JSON 的 `source_archive` 携带冻结视图，按稳定 message ID 幂等恢复，校验会话和消息归属；运行中的请求记录仍留在本机数据库。SQLite 在线备份包含所有新表。普通会话消息只增加轻量 `source_summary`，来源片段按需读取，不回传内部范围或完整工具证据。

GET 接口：

- `/api/agent/sessions/{sid}/messages/{mid}/sources`
- `/api/agent/sessions/{sid}/messages/{mid}/sources/{source_id}?snapshot_id=...`
- `/api/agent/runs/{rid}/sources`

回答、来源和快照逐级校验归属；删除会话不可再访问其记录。读取来源不生成快照、不改写会话 JSON，也不查询当前知识正文。旧记录仅展示留存证据并标记未知发送范围。网页（包括实际注册的 `web_fetch`）、MCP 等尚未适配的知识工具会标记覆盖不完整。

`sources_updated` 在记录提交后发出，携带 revision 和轻量摘要，同时支持 SSE 与事件重放。面板关闭时不拉取来源，打开时合并更新并忽略旧 revision；异步结果校验回答身份，片段节点不随 token 和来源清单更新而重建。

均在临时 Workspace 或模拟 HTTP 界面中验证，不访问个人模型接口或修改用户知识库。

- `node tools/agent_sources_ui_check.js`：原始应用页面上的三个入口、引用选中、筛选、版本、复制、删除反馈、刷新、错误重试、异步隔离、流式节点/选区保持、事件幂等、键盘、深浅主题及手机宽度。
