# 知识库数据结构与关系层（v261008.2）

> 本文记录一次**底层数据结构变更**：实验升格为独立条目类型、知识库引入**类型化关系层**，
> 以及随之而来的索引结构、工具接口与前端筛选变化。变更前的口径见 git 历史与
> `.trae/rules/知识库条目命名规范.md`。
>
> 唯一事实来源仍然是 `Workspace/Knowledge/**/*.md`；SQLite 索引与图谱是**可重建的派生数据**。

## 一、为什么要改

变更前的两个结构性问题（2026-10-08 全库体检，194 条）：

| 问题 | 实测证据 |
| --- | --- |
| 实验与知识混存 | 110 条 `note` 里 25 条是"实验"类别词，与 85 条方法/原理/模型笔记同目录、同路由、同状态机；"加新实验报告"要在同一套下拉里做两套决定 |
| 通用基础知识无处安放 | 194 条里只有 1 条无项目归属、2 条多项目 → 通用方法（如亚像素质心五法）被硬挂在某个项目上，与项目私有知识混在一起读 |
| 关系不可用 | 图谱 1514 条边里 1140 条是标签共现，236 条显式引用**没有任何类型**；120/194 条无显式引用；41/85 条知识条目入度 0 → 问不出"哪些实验用了这条知识" |

## 二、对象层：六类 → 七类

新增第七类 `experiment`：

| 维度 | 迁移前（note + 实验类别词） | 迁移后（kind=experiment） |
| --- | --- | --- |
| 目录 | `Knowledge/Notes/` | `Knowledge/Experiments/` |
| 前缀 | `知识-实验-` | `实验-` |
| 状态机 | 草稿 / 整理中 / 稳定 / 已归档 | 计划 / 进行中 / 完成 / 受阻 / 已归档 |
| 日期字段 | 无 | `record_date`（执行日期） |
| 标记 | 手写 `experiment` | 自动补 ⚗ `experiment` |
| 正文骨架 | 摘要 / 正文 / 关联 | 摘要 / 目标与假设 / 配置与参数 / 数据与口径 / 结果 / 结论与失效模式 / 留档路径 / 关联 |
| 命名校验 | 类别词必填 | 名称段须含实验编号（`（4.1）`），无编号规范的课题豁免 |

配套约束：

- `实验` 不再是合法类别词（`知识-实验-…` 会命中 **T020 error**，工具给出迁移提示）；
- `mcp/naming.py` 的编号校验（T017）改为按 `kind == "experiment"` 判定；
- 新增 `kb_change_kind` 工具做**结构性迁移**：`id`/`created` 不变，目录随动、标题前缀改写、
  H1 同步、状态映射、标记补齐、可选重写全库交叉引用。这是 `kind` 字段唯一的合法变更途径
  （通用 `kb_update_entry` 仍然拒绝改 `kind`）。

## 三、关系层：关联段 → 类型化边

### 语法

在正文「关联」小节里用固定小标题（或沿用历史行内标签）登记关系，**不需要新的 frontmatter 字段**：

```markdown
## 关联
### 依据的知识
- [[知识-方法-帧间稳像与链式配准]]：提供相似变换估计算法
### 用到的数据
- [[知识-数据集-DUST SET 1]]：878 帧人工标注，作 test
### 同系列实验
- [[实验-DUST 星图定姿（4.6）]]
### 上一环节
- [[实验-DUST 星图定姿（4.6）]]
### 产出与汇总
- [[总结-DUST 星图背景在轨链路（4.5 索引 → 4.8b 状态反演）]]
```

### 关系类型矩阵

| 关系 id | 显示 | 触发位置 | 含义 |
| --- | --- | --- | --- |
| `uses-knowledge` | 依据知识 | `### 依据的知识`｜行内 `方法条目/原理条目/模型条目/架构条目/知识条目/依据/参照` | 结论建立在哪条知识上 |
| `uses-data` | 使用数据 | `### 用到的数据`｜行内 `数据/数据集` | 数据来自哪个数据集或产物 |
| `cites` | 引用文献 | `### 引用文献`｜行内 `文献/引用` | 依据或对照的外部文献 |
| `series` | 同系列 | `### 同系列实验`｜行内 `同系列/系列` | 同一课题线的其它实验 |
| `chain-prev` / `chain-next` | 上一/下一环节 | `### 上一环节` / `### 下一环节`｜行内 `上一步/前置`、`下一步/后续` | 实验链条顺序 |
| `produces` | 产出汇总 | `### 产出与汇总`｜行内 `汇总/全链汇总/报告` | 归集到的总结、里程碑 |
| `wikilink` | 显式引用 | 其余任何位置 | 保底类型（向后兼容） |

实现单一事实来源：`app/store.py` 的 `RELATION_SECTIONS` / `RELATION_LABELS` / `iter_body_links()`。
**历史条目无需改动**：行内标签（`- 方法条目：[[…]]`）会被识别成对应类型，未命中的链接记为 `wikilink`。

### 索引与数据库变更

| 变更 | 内容 |
| --- | --- |
| `SCHEMA_VERSION` | 2 → **3** |
| `document_links` | 主键由 `(doc_id, token)` 改为 `(doc_id, token, role)`；旧库检测到缺 `role` 列时**整表重建**（纯派生数据）并强制重索引 |
| `graph_edges` | 类型化边与通用 `wikilink` 边**双写**：只认 `wikilink` 的旧消费方（含前端默认筛选）不受影响 |
| 重索引 | 版本不一致或 `force=True` 时全量重建；迁移记录见 `System/schema.json` |
| 静默跳过修复 | `sync()` 原来把索引异常（`OSError`/`UnicodeError`）静默丢弃，导致条目"凭空消失"；现改为在返回结果里给出 `skipped` 列表 |
| 归属归一化修复 | `store._normalize_projects()` 原来只同步 `projects`/`project`，清空归属时会留下 `project_id`/`project_ids`，索引（`document_projects` 同时看名字与 id）仍按项目计入 → 幽灵归属；现改为名字清空时同步清 id |

### 内容补录（同批次，证据驱动）

结构就位后，关系层最初只有「知识」一半接通（`uses-knowledge` 47、`uses-data` 0、`cites` 0）。
同批次按**既有正文证据**补齐，不发明引用：

| 补录 | 证据 | 结果 |
| --- | --- | --- |
| 5 条数据集条目 | 实验正文反复点名这些数据集，但库里只有一个选型总览条目 | `知识-数据集-DUST 在轨实测（SET 1 / SET 2）`、`NUAA-SIRST`、`IRSTD-1K`、`NUDT-SIRST`、`SIRST-v2（已退出评测口径）`；体量、划分、口径只写已确证内容，未确证字段标"待补" |
| 实验 → 数据 | 该实验正文自己点名了数据集 | `uses-data` 25 条边（DUST 10、NUAA-SIRST 7、IRSTD-1K 3、NUDT-SIRST 3、SIRST-v2 2） |
| 条目 → 文献 | 文献题名（去前缀、≥8 字）**完整出现**在该条目正文里，原先只是纯文本 | `cites` 50 条边，26 个条目获得 `### 引用文献` 小节 |
| 通用基础知识 | 17 条教科书级方法（亚像素质心五法、Top-Hat/LCM/SR/IPI、CKF/SCKF/EIF/IF、LQDG/Stackelberg/Minimax） | 清空项目归属 + 打 `通用基础` 标签；未归属条目由 1 条增至 23 条（含 5 条数据集条目与导航条目） |

补录脚本按"证据驱动、只做加法"编写：不匹配就跳过，跑完自动重建索引。**每次编辑前重读磁盘正文**——
同一批里「补数据关系」与「补文献引用」都会改同一个「关联」段，若沿用批次开始时的内存快照，
后一步会把前一步的编辑覆盖掉（本批次实际踩到过一次，已修正并重放核对）。清单见 `System/activity.jsonl` 的 `doc_create` / `doc_update` 事件。

迁移脚本可重复运行（幂等）；已迁移条目再跑会报告"没有需要迁移的条目"。

## 五、通用基础知识怎么放

- 归属：`projects` 留空（不挂项目），标签打 `通用基础`；
- 读取：`kb_list_entries(unowned=true)` 或前端「未归属项目（通用基础）」/`仅未归属`；
- 使用关系仍可追溯：项目侧实验通过 `### 依据的知识` 指向它，图谱与知识树都能看到"被哪些项目的实验引用"；
- **不建"通用基础"伪项目**：项目维度被仪表盘、里程碑、待办与项目面板共用，伪项目会污染统计；
- **数据集条目同样不挂项目归属**：数据集/文献是"可引用对象"，被谁用由 `uses-data` / `cites` 边承载（如 DUST 由 10 个实验引用）。若希望某个数据集出现在项目面板里，用一次 `kb_update_entry` 把 `projects` 填回即可；
- 当前已标注 17 条通用方法、5 条数据集条目，另有 1 条全库导航条目本就无归属 → 未归属条目共 23 条。

## 六、论文引用层（预留）

同一套关系语法直接复用，无需新结构：

```markdown
## 引用清单
### 依据的知识
- [[知识-方法-小目标检测评测指标体系]]
### 实验
- [[实验-传统单帧经典方法对比（1.2）]]
### 用到的数据
- [[知识-数据集-NUAA-SIRST]]
### 引用文献
- [[文献-…]]
```

- 非文献条目的稳定引用键：`KB-<kind 首字母>-<id 后 6 位>`（如 `KB-E-3c4d5e`、`KB-K-a1b2c3`）。
  条目 `id` 不可变，改名不断链；文献仍走 `cite_key` + BibTeX 导出。
- `Knowledge/Exports/KnowledgeBundles/`（邻域打包导出）与 `tools/kb_tree.py` 是现成的导出底座。

## 七、已知陷阱与后续

**陷阱**

1. `import app.indexer` 作为**首个** app 导入会触发 `workspace ↔ config` 循环导入而失败；
   正确顺序是先 `import app.config`（工具脚本已按此处理）。属既有问题，未在本次改动中修。
2. `Workspace/` 下的数据目录对受限进程只读（会话级授权缺口），迁移/重索引需要更宽权限执行。
3. 工作台 exe / MCP 服务是长驻进程：改完本仓库代码需**重启**才会加载新结构与新工具；
   重启前旧进程若刷新索引，会按旧口径重建（派生数据，重启后自动恢复）。

**后续可做**

- `series` 字段 + 系列分组 UI（把「同系列实验」从正文关系升级为可分组的字段）；
- UI 内嵌可折叠知识树（当前是生成式报告 + MOC 条目）；
- 数据集条目化（把 `Projects/*/Data` 与外部 `results/` 路径登记为 `知识-数据集-…` 条目）；
- `manuscript` kind：论文稿件作为引用收集器，直接导出"知识 / 实验 / 数据 / 文献"四组引用清单。
