# 日历（`milestone-calendar`）

把**里程碑的 `due`** 与**待办的 `due`** 汇成一份到期视图：逾期 / 今天 / 近期一目了然。

## 两个自登记点

| 位置 | 内容 |
| --- | --- |
| 侧栏「日历」（**核心工作** 组，待办之后、Agent 之前） | 月历（每周一起始，点某天看当天明细）+ 逾期 / 今天 / 近期 / 无日期四段清单 |
| **顶栏角标**（`nav[].slot = "topbar"`） | `⚠ 逾期数`、`◔ 今日数` 常驻显示；点角标跳到本页。没有到期项时显示 `✓ 到期` |

## 为什么不做"到点弹通知"

内核**没有通知通道**，操作系统级通知还要处理权限与打包差异。与其做一个会漏的假提醒，
不如把「逾期 / 今日」做成**顶栏常驻角标**——打开工作台就一定看得见。角标每 5 分钟自刷一次，
切回浏览器标签页也会立即刷新（所以刚在「待办」页完成一项，回到任何页面角标就是新的）。

真要推送，应当先在 [PLUGIN_SPEC §6.2 ③](../../docs/PLUGIN_SPEC.md) 的能力缺口里加一条**通知能力**，
再由插件消费；而不是让每个插件自己起线程轮询弹窗（那会变成幽灵线程 + 重复弹窗）。

## 数据与口径

- 里程碑：`core_api.entries("milestone")` 的 `due` 字段；`status` 为「完成/已归档」的不参与提醒。
- 待办：`core_api.todos(include_done=False)`（与 `/api/todos` 同源），完成的不参与提醒。
- 分桶：`overdue`（due < 今天）/ `today` / `soon`（今天 + N 天内，N = 近期窗口，默认 7）/ `later` / `undated`（没填 `due` 的）。
- 提醒只看**知识库里的日期字段**，不猜正文里的日期（猜错比不猜更糟）。

## 用法与接口

- 页面：近期窗口天数可改并保存（存 `config/plugins/milestone-calendar.json`）。
- 路由：`GET agenda`（含 `counts` 与 `buckets`）、`GET|POST config`。
- Agent 工具：`p_milestone-calendar__agenda` —— 问「有什么逾期/今天要做的」时用。

## 隔离

- 只读知识库与待办（`core_api` 只读窗口），只写自己的配置；
- 无后台任务（不需要调度：角标是查询，不是推送）；
- 前端只碰 `ERWPanels`（页面 + 槽位）、`erwFetch`、`ERWToast`，样式全部落在 `[data-plugin="milestone-calendar"]` 内；
- 内核源码里没有本插件的任何痕迹。
