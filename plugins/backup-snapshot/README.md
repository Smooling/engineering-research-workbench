# 备份与快照（`backup-snapshot`）

把**知识库本体与配置**打成带时间戳的 zip 快照：内核按间隔自动执行、按份数清理，可下载、可查看内容。

## 它保护什么、不保护什么

| | 说明 |
| --- | --- |
| **保护** | 误删/误改条目（`Workspace/Knowledge/**`）、项目/待办/插件状态（`System/*.json`）、设置与密钥（`config/app.json`、`config/secrets.json`、`config/plugins/*.json`）、活动日志——默认只收这些**小体积但丢了最疼**的东西（通常几 MB） |
| **默认不收** | 附件与 PDF（几百 MB）、项目里的数据文件、派生索引 `index.sqlite`（**可重建**，收了只是浪费空间）。三项都可以在面板里打开 |
| **不保护** | 磁盘故障——如果快照目录还在同一块盘上，就只防手滑。**建议把目标目录改到外部盘或同步盘**（面板里可填绝对路径） |
| **不做自动恢复** | 覆盖用户数据是破坏性动作。面板提供「查看内容」（列出快照里有多少文件、生成时间、内核版本）与下载，恢复由你解压覆盖，插件**不替你写回** |

## 怎么工作

- **调度**：由内核的后台任务（`ctx.jobs`，v261009.24 起）负责。插件注册一个名为 `auto` 的任务，
  内核每 30 分钟检查一次，达到「自动间隔」（默认 24 小时）才真正执行；
  插件自己**不起线程**——否则热重载后会留下幽灵线程。
- **幂等**：执行前先看 `state.json` 里的上次备份时间，距上次不足间隔就跳过。
  所以「重启工作台」或「在设置页开关插件」都不会触发多余备份。
- **原子**：先写 `.<name>.zip.part`，成功后再改名——任何时刻都不会留下半个快照。
- **清理**：只删**本插件生成的** `snapshot-*.zip`，按「保留份数」保留最新的 N 个；
  目标目录里别人的文件一个都不碰。

## 用法

1. 「设置 → 插件」启用（默认不启用）；侧栏出现「备份快照」；
2. 首次进来建议：把**目标目录**改成外部盘 → 保存设置 → 「立即备份」；
3. 之后每天自动一份；需要时「查看内容」确认，再下载手工恢复。

Agent 侧工具：`p_backup-snapshot__snapshot_now`（立刻备份）、`p_backup-snapshot__list_snapshots`（列快照）。

## 快照里有什么

```text
snapshot-20261010-160000.zip
├─ manifest.json                      ← 生成时间/原因/内核版本/选项/文件数/原始字节/跳过的文件
├─ Workspace/Knowledge/...            ← 知识条目（Markdown + frontmatter，唯一事实来源）
├─ Workspace/System/todos.json        ← 待办、项目注册表、插件启停状态、活动日志
├─ config/app.json 等                 ← 设置与插件配置
└─ （可选）Projects 文本 / 附件 / index.sqlite
```

## 隔离边界

- 写入只落在自己的命名空间 `Workspace/System/Plugins/backup-snapshot/`，或用户在设置里显式指定的外部目录；
- 读取用 `core_api.data_root()` 枚举 `Workspace/**` 与 `config/**`——这是备份这类插件的正当用途
  （`core_api.data_root()` 的说明里已明确列出）；**不使用** `core_api.entries()` 那种条目级窗口，
  因为备份要的是**磁盘上的真实文件**（含索引未收录或尚未同步的内容）；
- 不改任何知识条目，所以它的工具不是「写工具」、不走内核的草稿确认闸门。
